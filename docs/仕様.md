# 計算の仕様

ゆけ！勇者 ツール集の計算の仕様、データの説明、推測で決めたことをまとめた文書です。
計算を変えたら、この文書と `tests/` のテストも直してください。

## 共通の決まり

- 「30%増」などの端数は切り上げ。

## データ（data/*.json）

出典は ゆけ!勇者 @ ウィキの [武器](https://w.atwiki.jp/yukeyuu/pages/13.html)・[防具](https://w.atwiki.jp/yukeyuu/pages/14.html)・[アイテム](https://w.atwiki.jp/yukeyuu/pages/19.html) のページ。
それを転記した表を `scripts/raw_sheet.py` に写してある。

武器の1件：

```json
{"rarity":4,"name":"アークブレイド","base_attack":70,"max_enhance":75,
 "base_text":"HP+10,防+15","base":{"hp":10,"atk":70,"def":15,"eva":0,"luk":0},
 "growth_text":"HP+2,攻+5,防+2,回+3","growth":{"hp":2,"atk":5,"def":2,"eva":3,"luk":0},
 "ability":null,"dungeons":["王"],"price":60000,"sell_price":6000}
```

- 防具は `base_attack` の代わりに `base_defense`。アイテムには `max_enhance` と `ability` がない。
- `base` は主ステータス（武器なら攻、防具なら防）込みの基本値ベクトル。
- 価格は元の表で「1,000」がカンマで割れていたので「売値＝価格/10」で復元（全件整合）。
- `resonances.json` は wiki の共鳴のページを転記した表から作った（変換スクリプトは残していないので、直すときは JSON を直接直す）。
  1件は `{"weapon","armor","name","effect","calc"}`。`calc` がステータスへの効果で、ステータスに関係ない共鳴は null。
  注記番号（`*1` など）は `effect` の文字列内、または `name_note` に残っている。注記本文は未取得。
- `enhance.json` は wiki を転記した強化上限値・費用の表（`scripts/raw_enhance.py` に写してある）から作る。
  1件は `{"kind":"weapon"|"armor","name","max","cost"}`。`max` は強化上限（マスタの `max_enhance` と全件一致）、`cost` は+1あたりの費用。
  費用はほぼ全件「価格の半分」。例外：漆黒の鎧は wiki の34,500のまま（規則なら40,000）、端午の鎧は wiki に費用がなく5,000と推測（`note` あり）。
  元の表の「鬼の金棒」「鬼のパンツ」はマスタの「オニの金棒」「オニのパンツ」。

既知の問題：

- 「ふるびた剣2」「ふるびた鎧2」は元データが「？」なので null。UIでは除外している。
- アビリティ等の注記番号（`*1`〜`*12`）は文字列のまま。注記本文は未取得。
- アイテムの入手方法（宝箱／ドロップ／ショップ等）は元の表のセル色だったため取れていない。
- 粽大刀の `base_text` は「HP防運+5,回+55」だが、数値列は hp0 / def0 / luk5 / eva55。元の表の不整合の可能性あり。

## 成長予測（src/calc）の仕様

### ステータス（engine.js `build`）

- 初期値 HP30・攻5・防5・回5・運5。
- 神様の加護：武器を装備せずに出発すると攻（戦いの神様）、防具を装備せずに出発すると防（守りの神様）が+2〜3。
  ゲームでは2か3だが、成長値と同じく平均の+2.5で計算する（メンテナー判断）。初期値に足すので、Lv1 は切り上げで+3 になる。
  画面の選択は不要で、欄が空なら自動で入る（総当たりも同じ）。
- 素の成長値（1Lvあたり平均）5.5 / 2.5 / 2.5 / 2.3 / 1.1。
- 基本値＝武器 base（攻＋強化値）＋防具 base（防＋強化値）＋道具 base。
- 成長補正＝武器 growth＋防具 growth＋道具 growth。
- Lv1 ＝ 初期値＋基本値。成長値 ＝ 素の成長値＋成長補正。
- Lv N ＝ 切り上げ（Lv1 ＋ 成長値 ×（N−1））。

端数は切り上げ。wiki の森表がこれで全マス一致する。切り捨てで計算すると値が1ずれることがある。

アビリティ倍率（増加分は切り上げ、割合は足し算で合成）：

| アビリティ | 効果 | 持っている装備・道具 |
|---|---|---|
| 防具基本値UP | 防具 base ×1.3 | 光輝の剣 |
| 防具基本値2倍 | 防具 base ×2 | 桜橘の刀 |
| 防具成長補正UP | 防具 growth ×1.5 | オニの金棒 |
| 武器基本値UP | 武器 base ×1.3 | 太陽の鎧 |
| 武器成長補正UP | 武器 growth ×1.5 | オニのパンツ |
| 武器基本値100%増 | 武器 base に +100% | 道具「力餅」 |

HPの成長値は1.0未満にしない（下の推測事項1を参照）。

### 共鳴（engine.js `resonances` / `build` の第6引数）

- 武器側と防具側の素材名のどれかが組み合わせに合えば発動する。合成装備は `parts` に素材名を持ち、両方の素材の共鳴が出る
  （例：鉄のナイフ＋金の斧 × 鉄の鎧＋金の鎧 → 連続攻撃(微)と金貨泥棒(強)）。メンテナー確認済み。
- ステータスに効くもの：
  - 生命アップ（バスター一式）：Lv1 の HP+30。ほぼ使わない装備なので厳密さは不要。
  - 運アップ(微/弱/中/強)（鉄/銀/金/ダイヤの剣×鎧）：運の出発時補正 +10/20/30/40。
  - 基本値アップ（セラミック一式）：攻・防の出発時補正 +30。
  - 負ステータス耐性（ダーク一式）：装備・道具の負の基本値・成長補正を0にする（倍率を掛ける前）。
  - 出発時補正の加算は、アビリティ倍率の外で足す。複数発動したら合計する。
- **保留**：ステータスアップ（ディフェンダー×オフェンサー、「武具の攻防が1.3倍」*2）。掛かり方が不明なので未反映。画面には「ステータスへの効果は未反映」と出す。
- 戦闘中だけの効果（ランダムアップ・硬化・端午）や、特定の場所・敵への効果は入れない。
- 確認は `docs/実機テスト.md`。実際のゲームではまだ確かめていない。

### 出発時レベル（engine.js `startExp` / `startLevel`、`build` の戻り値 `exp` `start`）

- 装備のアビリティと道具の「経験値+N」を合計する（経験の木の葉+50、経験の木の大葉+100、ターキーメイル+100）。重ねたら足す。
- 必要経験値（累計）はメンテナーが調べた経験値テーブル（一部）：Lv2=10, Lv3=40, Lv4=90, Lv5=160, Lv6=250（10×(Lv−1)² の形）。
  最大の組み合わせ（大葉×2＋ターキーメイル＝300）でも Lv6 までに収まる。
- 出発時のステータスは Lv1 から普通に上げた場合と同じ（式は変えない）。メンテナー確認済み。
- 画面：予測表は出発時レベルから表示し、その行に「（出発）」を付ける。内訳表に「出発時 LvN」の行を出す。
- 森：「Lv1」の条件（4F切捨の HP≥50、加点1の HP≥70）は出発時レベルで判定する。Lv8・10・12・14 の条件はそのまま。

### 鍛錬の森4F点数（engine.js `forest`）

出典は wiki「[鍛錬の森・武器防具組み合わせ例](https://w.atwiki.jp/yukeyuu/pages/106.html)」。

- **4F切捨基準**：HP Lv1≥50、ATK Lv10≥98 かつ Lv14≥116、DEF Lv10≥219 かつ Lv14≥272。
  満たさない組み合わせは wiki の表で空欄になる。
- **8F切捨基準**（参考、点数なし）：Lv50 で HP≥400、ATK≥324、DEF≥440。
- **対4F基準**：15項目の加点式で、満点99（HP26・ATK37・DEF36）。
  ATK の項目は Lv8 と Lv12 の**両方**を満たす必要がある。wiki の盗賊のナイフ行で確認済み。

### 合成（engine.js `synth`）

出典は wiki「[合成屋](https://w.atwiki.jp/yukeyuu/pages/111.html)」。

- 基本値・出発時補正・成長補正：ステータスごとに2つのうち高い方。
- 強化値：2つの平均の切り上げ。レア度：2つの合計。
- アビリティ・共鳴：両方を引き継ぐ。
- 合成鉱：合計レア度以上の番号が必要。
- 合成時間：合計レア度 × 合計強化値 × 5分。
- 合成金額：（+0の合計価格）×（合計レア度×0.2 ＋ 合計強化値×0.02）。
- 合成後の装備は、それ以上の強化・合成ができない。
- 神の祝福：合成後に最大+3。本来の最大値を超えられる。
- 画面の合成モードでは、素材ごとの強化値と祝福は入れない。「合成後の強化値（祝福込み）」を1つだけ入れる（メンテナーの方針）。
  最大は「素材が強化値MAXのときの合成後の値＋3」。合成時間・金額は素材が強化値MAXのときの値を出す。

### 総当たり（search.js `makeSearch`）

- 言語は JavaScript のまま（将来ウェブで公開するため。計算エンジンを画面と共有できる）。
- 画面では Web Worker を CPU コア数ぶん（最大8）立てて、武器×防具の組を分担する。
  Worker のコードは `<script id="core">`（engine＋search）の中身を Blob にして作る。Worker が使えなければ画面側で少しずつ回す。
- 速度：1通り約11µs（1スレッド）。全通り（武器49×防具40×道具1,128＝約221万）は4コアで約7秒。
  そのため `vec` / `add` を直書きにし、`build` の `at` をレベルごとにキャッシュしている。
- 目的は「理論上のベスト」を知ること。総当たりする武器・防具は、基本は強化値MAX。
  候補の一覧で装備ごとに強化値を入れると、その値（上限まで）で計算する（武器と防具を同時に鍛えている途中などを想定。#7）。空欄なら MAX。
  指定は候補のチェックと一緒に localStorage（`yuke-calc-cands` の `enh`）に保存する。
  チェックしていない欄は今の選択（合成も可）で固定。
- 「合成も探す」（武器・防具それぞれ）：候補の違う装備2つを、上の強化値（指定がなければMAX）の素材で合成し、神の祝福+3で計算したものを候補に足す。
  同じ装備どうしはゲームの仕様で合成できない（意味もない）ので入れない。
  合計レア度の上限を選べる（2〜10、初期値4）。ゲームでは合計レア度で合成に使う消費アイテムが変わり、今は4まで実装、過去は7まであった。
  候補の数（全装備が候補のとき、素の装備込み）：上限4で武器282・防具220、上限7で975・709、上限10で1,225・820。
- 「反映」で合成の結果を選ぶと、その欄を合成モードにして素材と、合成後の強化値（祝福+3込み）を入れる。
- 道具を両方回すときは順番違いを1つにまとめ、同じ道具2つも含む。「なし」も候補に入る。
- 並べ替え：森4Fの点数（同点なら Lv14 の HP+攻+防）、または指定レベルの HP/攻/防/回/運。「4F切捨基準を満たすものだけ」で絞れる。
- 「反映」で、総当たりした欄だけを上の選択に入れる。
- 目安の時間は、2秒以上かかった実行の実測（localStorage キー `yuke-calc-speed`、1通りあたりの秒数）から出す。実測がなければ 11µs÷並列数。
  目安が30秒以上（ui.js `LONG_SEC`）なら ⚠ と注意文を出す。

## 強化屋（src/enhance）の仕様

出典は wiki「[強化屋](https://w.atwiki.jp/yukeyuu/pages/58.html)」（メンテナーが確認した内容）と、メンテナーからの説明。

- 同じ装備を2つ選ぶ（例：ショートソード+1 と ショートソード+2）。2つ目（素材）の強化値 b の回数だけ判定する。
- 1回の判定で+1。クリティカル（ボーナス）なら+2。失敗はない。
- クリティカル率は約「強化屋Lv%」（Lv30なら30%）。Lv2 から起きる（Lv1 は0%）。強化屋Lvの最大は99。
- 結果＝ベース a＋b＋クリティカル回数。そのあと神の祝福で+3。どちらも強化上限を超えない（例：198になったショートソードは+3しても200）。
- 費用＝+1あたりの費用×b、時間＝強化鉱の数字（20/40/60 分）×b。強化鉱で費用は変わらない。上限を超えた分も費用・時間はかかる。
- 計算（engine.js `enhance`）：クリティカル回数は二項分布。対数で計算してアンダーフローを避ける（判定500回・99%でも可）。乱数は使わない。
  上位 t＝「これ以上になる確率が t 以上」の一番高い値、下位 t はその逆。
  「上限に届く」は上限ちょうども含む確率（＝目標を上限にしたときと同じ）。「超えて無駄が出る」（`capP`）は祝福まで足して上限を超えた場合だけ。`byLevel` は Lv1〜99 の期待値・下位10%・上位10%・上位1%。
- 画面：入力（装備・ベース・素材・強化屋Lv・強化鉱・祝福・目標）、結果（期待値、最低・下位10%・期待値・上位10%・上位1%・最高の6つ（中央値は出さず期待値に統一）、目標以上の確率、上限で止まる確率、費用・時間）、
  結果の分布の棒グラフ（目標以上は金色、期待値・上位10%・上位1%の線）、強化屋Lvごとの期待値と下位10%〜上位10%の帯。どちらも数値の表つき。
  分布グラフは確率0.01%未満の端を描かない（表には全部出す）。
- テスト：wiki の例（+1＋+2→+6、198→200）、乱数20万回との一致、費用・時間、データとマスタの整合、進行中の強化（ゲーム画面の例）。

### 進行中の強化（engine.js `progress`）

- 入力は「強化を始めた日時」（年/月/日 時:分 の5つの欄。ブラウザの日時入力は年が6桁まで入り次へ進まないので自前。年4桁・ほか2桁で次の欄へ進む）と「最新ログの『+○○へ強化された』の数字」。ベース・素材・強化鉱・強化屋Lvは上の欄を使う。今の時刻はページで取る（開いている間は20秒ごとに更新）。
- 判定は開始から強化鉱の分数ごとに1回（9:22開始・強化鉱60なら 10:22, 11:22, …）。判定済み n＝floor((今−開始)÷分数)、素材の数 b が上限。日付をまたぐ強化（3日など）も同じ式。
- クリティカル回数 k＝(最新ログの数字 − ベース) − n。0≤k≤n でなければ入力ミスとして知らせる。最新ログが上限なら「k回以上」。
- 上振れ／下振れ：n回・Lv%の二項分布で、k回以上の確率が25%以下なら上振れ、k回以下の確率が25%以下なら下振れ、それ以外は「ほぼ期待どおり」。Lv1 は「Lv1 はクリティカルなし」。
- 最終の見込み・はじめの見込み：残り b−n 回を確率どおりに進めたときの期待値と80%の範囲。祝福は上の「神の祝福」の選択に従い、カッコ内に「祝福込み」／「祝福なし」と書く（メンテナー指示）。
- 例（ゲーム画面）：鉄の鎧+8 に +4、強化鉱60、9:22開始。12:30に最新ログ+12 → 判定3回・クリティカル1回。

### 逆引き（engine.js `reverse`）

- 目標の強化値（上の「目標の強化値」）に届く確率が 90%・75%・50%・10%（`REVERSE_PROBS`）以上になる、一番小さい素材の強化値を出す。確率はユーザーが入力しない（メンテナー指示）。
- ベース・強化屋Lv・祝福・装備の上限は上の欄を使う。素材は装備の上限まで。上限まで使っても届かない確率は「届かない」。
- b を増やすほど届く確率は上がるので二分探索。表には「そのときの確率」（実際の確率）も出す。費用・時間は出さない（メンテナー指示）。

## 推測で決めたこと（要確認）

1. **HP成長の下限**：成長値が1.0を下回らないようにしている。はっきりした出典はない。
2. **倍率アビリティの重ね方**：足し算で合成（例：+30%と+100%で×2.3）。実際のゲームでの確認は `docs/実機テスト.md` #10。
3. **同じアビリティの重複**：合成の両素材が同じアビリティを持っていても1回分として扱う。
4. **合成後の最大強化値**：素材の最大強化値の平均（切り上げ）。MAX表示の判定だけに使う。wiki 注釈の例と整合する。
5. **神の祝福**：+0〜+3。画面では合成後の強化値に込みで入れるので、祝福を別に選ぶ欄はない。総当たりでは+3。
6. **強化屋のクリティカル率**：wiki は「おおよそ強化屋Lv%」。ちょうど Lv/100 として計算している。
   Lv1 は0%：wiki の「強化屋Lvが2以上では稀に…+2となる」からの読み取り（Lv1 で起きないとは明記されていない）。メンテナーはこの扱いで了承。画面の「計算のしかた」には Lv1 の記述を書かない（メンテナー指示）。
7. **強化屋の祝福**：使う／使わないを選べる扱い（+3 か なし）。
